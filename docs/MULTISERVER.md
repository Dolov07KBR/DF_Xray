# Мультисервер: несколько нод под одной панелью

Панель управляет любым количеством серверов Xray: конфиг, клиенты, лимиты и
статистика — в одном месте, а сами серверы могут стоять у разных провайдеров.
Схема pull: агент на ноде сам опрашивает панель, поэтому нодам не нужны
входящие порты панели и белый IP, кроме собственного порта Xray.

```
                    ┌────────────────────────────┐
   браузер ───────► │  Панель (HTTPS, 8000/443)  │
                    │  SQLite: клиенты, ноды,    │
                    │  трафик, настройки         │
                    └───────┬──────────┬─────────┘
                            │ pull     │ pull
                   ┌────────▼───┐  ┌───▼────────┐
                   │ Сервер 1   │  │ Сервер 2   │
                   │ Xray+агент │  │ Xray+агент │
                   └────────────┘  └────────────┘
```

## Как добавить сервер

1. **Узлы → Добавить сервер** — название, адрес, порт, протокол и транспорт.
   Регион показывается в карточке. Reality-ключи сгенерируются автоматически
   (кнопка «Сгенерировать Reality-ключи» в форме тоже есть).
2. В карточке сервера нажмите **Подключить** — панель покажет команду установки
   и три варианта: одна команда (systemd), Docker, docker-compose.
3. На новом сервере от root:

   ```bash
   curl -fsSL https://panel.example.com/api/node/install/<install_token>.sh | sudo bash
   ```

   Скрипт идемпотентен: ставит Xray (официальный installer), Python 3 и агент,
   создаёт systemd-сервис `dfxray-node`, запускает его и ждёт первый конфиг.
4. Откройте порт ноды (по умолчанию 443/tcp) в фаерволе провайдера и локально:
   `ufw allow 443/tcp`.
5. Через 30 секунд сервер станет «Онлайн» в панели и получит конфиг со всеми
   активными клиентами.

### Требования к панели

- Агент обращается к панели, поэтому панели нужен **публичный HTTPS-адрес**
  (домен + Caddy из `install.sh`, или nginx). Без HTTPS токен ноды идёт по сети
  открытым текстом — панель предупреждает об этом в окне «Подключить».
- Адрес берётся из настроек: `DFX_BASE_URL` / поле «Публичный адрес панели».
  Если меняете домен — обновите его, иначе новые ноды получат старый URL.

### Ссылка установки

- Токен установки хранится отдельно от токена агента. «Перевыпустить ссылку»
  ломает старую команду, но **не** отключает уже подключённые серверы.
- Токен агента перевыпускается отдельно в окне «Конфиг» — после этого нужно
  обновить `DFX_NODE_TOKEN` на сервере и перезапустить агент.

## Клиенты на нескольких серверах

- По умолчанию клиент попадает на **все включённые серверы** (в подписке
  появляется по ссылке на каждую ноду).
- В карточке клиента есть чекбоксы «Ноды»: отметьте только нужные серверы,
  чтобы, например, не выдавать зарубежную ноду клиентам из России.
- Группы клиентов, лимиты трафика и сроки работают общие: трафик суммируется
  со всех серверов, при исчерпании лимита агент отключает клиента на всех.

## Что панель знает о серверах

Агент присылает heartbeat каждые 30 секунд: версию Xray и агента, состояние
процесса Xray, uptime, load average, использование памяти и ревизию конфига.

| Поле | Где видно | Смысл |
| --- | --- | --- |
| `status` | карточка, «Агенты нод» | онлайн, если heartbeat моложе 2 минут |
| `health` | бейдж | `degraded` — агент на связи, но Xray не запущен |
| `cfg_revision` | карточка, конфиг | ревизия конфига, применённая на сервере |
| `last_error` | карточка, «Конфиг» | ошибка `xray -test` или применения конфига |

Страница **Узлы → Агенты нод** — таблица всех агентов: статус, версия, Xray,
uptime, LA1, память, ревизия и время последнего heartbeat.

## Порты и сертификаты

- Reality не требует сертификата: маскировочный домен берётся из SNI/dest,
  подобрать его можно сканером целей в разделе «Входящие».
- Для TLS-нод сертификат выпускается автоматически: укажите в поле **SNI** домен,
  который уже смотрит A-записью на ноду, заполните «E-mail для Let's Encrypt» в
  **Настройках → Подписки** и выполните команду «Подключить». Скрипт поставит
  `certbot`, выпустит сертификат `--standalone` и положит симлинки в
  `/etc/xray/cert`. Подробнее: [SECURITY.md](SECURITY.md#автовыпуск-tls-сертификатов).
  Если сертификат уже есть (например, wildcard), просто укажите свои пути в форме
  ноды — автовыпуск в этом случае не нужен.
- Порт ноды не обязан быть 443: для TLS с Caddy панель на 443 использует 8443
  для ноды (так делает `install.sh --domain`).

## Вывод сервера: drain и миграция клиентов

Перед тем как погасить сервер, выведите его из подписок — текущие подключения
не оборвутся, а новые клиенты его уже не получат:

```bash
# 1. drain: нода остаётся в панели и в Xray, но исчезает из новых подписок
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"drain": true}' https://panel.example.com/api/nodes/<id>/drain

# 2. перевести закреплённых за нодой клиентов на другую ноду
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"to_node_id": 2}' https://panel.example.com/api/nodes/<id>/migrate

# 3. вернуть в работу, если передумали
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"drain": false}' https://panel.example.com/api/nodes/<id>/drain
```

То же самое есть в интерфейсе: в карточке ноды кнопки с иконкой питания (drain)
и маршрута (перевод клиентов). Порядок вывода сервера, влияние на подписки и
сортировка нод по задержке описаны в [OPERATIONS.md](OPERATIONS.md).

## Обслуживание

```bash
# статус агента
systemctl status dfxray-node
journalctl -u dfxray-node -f

# обновить агент (повторный запуск команды установки)
curl -fsSL https://panel.example.com/api/node/install/<token>.sh | sudo bash

# перезапустить
systemctl restart dfxray-node
```

Логи агента пишутся в journald. Агент сам перезапускает Xray при падении и
применяет новый конфиг только после успешного `xray -test`.

## Docker вместо systemd

```bash
docker run -d --name dfxray-node --restart unless-stopped \
  -e DFX_PANEL_URL=https://panel.example.com \
  -e DFX_NODE_TOKEN=<agent token> \
  -p 443:443 \
  -v dfxray-node:/etc/xray \
  ghcr.io/dfxray/node:latest
```

Или добавьте сервис из вкладки «docker-compose» в свой `docker-compose.yml`.
Для нод, поднятых через `install.sh` на том же сервере, это уже сделано
(`node-de`).

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Сервер «Не подключалась» | `curl -I https://panel.example.com/healthz` с сервера, токен в сервисе |
| «Xray не работает» | `journalctl -u dfxray-node`, `xray -test -config /etc/xray/config.json` |
| `last_error: xray -test …` | несовместимая пара транспорт/протокол, путь к сертификату |
| Клиент не подключается | порт ноды закрыт, домен не резолвится, SNI не совпадает |
| Нет статистики | Xray API на `127.0.0.1:10085`, агент запущен от root |
