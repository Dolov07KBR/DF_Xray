# Безопасность панели: 2FA, API-токены, TLS

Документ описывает три механизма, появившихся в 1.3.0: двухфакторную
аутентификацию администратора, API-токены для автоматизации и автовыпуск
TLS-сертификатов для TLS-нод.

## Двухфакторная аутентификация (TOTP)

Панель → **Настройки → Безопасность → Двухфакторная аутентификация**.

1. «Включить 2FA» → панель показывает QR-код и секрет для ручного ввода.
2. Отсканируйте код в Google Authenticator, Aegis, 1Password, Bitwarden или Raivo.
3. Введите текущий шестизначный код — панель включит 2FA и выдаст 8 резервных кодов.
4. Резервные коды показываются **один раз**: каждый код одноразовый и после
   использования сгорает. Перевыпуск — кнопкой «Новые резервные коды» (нужен пароль).

Что происходит под капотом:

- TOTP по RFC 6238 (SHA-1, 6 цифр, шаг 30 секунд), реализация на стандартной
  библиотеке (`app/totp.py`), окно проверки ±1 шаг на дрейф часов.
- Секрет и хэши резервных кодов хранятся в таблице `admins`; резервные коды —
  PBKDF2, в открытом виде их нет.
- Включение и выключение 2FA завершают все активные сессии.

Поток входа:

```
POST /api/auth/login {"username": "...", "password": "..."}
  → {"totp_required": true, "challenge": "...", "username": "..."}   (cookie не выдаётся)

POST /api/auth/login {"username": "...", "challenge": "...", "code": "123456"}
  → 200 + Set-Cookie: dfx_session
```

`challenge` живёт 300 секунд, одноразовый и подтверждает, что пароль уже проверен:
повторно присылать пароль на втором шаге не нужно. Неверный код не «сжигает»
challenge, поэтому опечатку можно исправить в пределах тех же 5 минут.

Если 2FA включена, а токен автоматизации нужен — создайте API-токен заранее:
`tools/loadtest.py` и любые скрипты умеют работать по Bearer-токену без кода.

## API-токены

Панель → **Настройки → Безопасность → API-токены → Создать токен**.

- Значение токена (`dfx_…`) показывается один раз, в базе лежит только SHA-256 хэш.
- Уровни доступа: `read` (только `GET`/`HEAD`) и `write` (любые методы).
- Срок действия задаётся в днях; `0` — бессрочно.
- В списке видно префикс, автора, дату создания, последнее использование и срок.
- Удаление токена мгновенно отзывает доступ.

Запросы с токеном не требуют CSRF-заголовка и cookie:

```bash
TOKEN=dfx_xxxxxxxx

curl -s -H "Authorization: Bearer $TOKEN" https://panel.example.com/api/users
curl -s -H "Authorization: Bearer $TOKEN" https://panel.example.com/api/dashboard

# токен с уровнем read на write-запрос получит 403
curl -s -X POST -H "Authorization: Bearer $TOKEN" \
     -H 'Content-Type: application/json' -d '{"username":"tmp"}' \
     https://panel.example.com/api/users
```

Типичные сценарии: Prometheus-экспортёр, бэкап-скрипт на отдельном хосте,
CI, интеграция с ботом поддержки, нагрузочные тесты.

## Автовыпуск TLS-сертификатов

Раньше сертификат для TLS-ноды нужно было класть в `/etc/xray/cert` вручную.
Теперь скрипт установки ноды умеет выпускать его сам.

1. В **Настройки → Подписки** заполните «E-mail для Let's Encrypt» (необязательно,
   но нужен для писем об истечении).
2. Создайте ноду с `security = tls` и укажите в поле **SNI** домен, который уже
   указывает A-записью на этот сервер.
3. Нажмите «Подключить» и выполните команду на сервере ноды.

Скрипт:

- ставит `certbot` из пакетов дистрибутива (apt / dnf / yum);
- выпускает сертификат `certbot certonly --standalone` на домен из SNI;
- кладёт симлинки `fullchain.pem` / `privkey.pem` в `/etc/xray/cert`;
- если выпуск не удался (занят порт 80, DNS ещё не переключился) — пишет
  предупреждение и продолжает установку, чтобы Xray не остался без конфига.

Требования: свободный порт **80** на время выпуска, DNS-запись домена на ноду,
доступ в интернет. Продление — стандартный `certbot.timer`; перезапуск Xray после
продления можно повесить на hook:

```bash
certbot renew --deploy-hook 'systemctl restart xray'
```

Проверить, что сертификат на месте:

```bash
openssl x509 -in /etc/xray/cert/fullchain.pem -noout -subject -dates
```

## Что ещё стоит знать

- Панель не хранит пароли в открытом виде: PBKDF2-SHA256, 210 000 итераций.
- Сессии — в SQLite, cookie `HttpOnly` + `SameSite=Lax`, `Secure` при HTTPS.
- Защита от перебора: ограничение попыток входа по IP, журнал `auth.2fa_failed`.
- Все действия с 2FA, токенами и уведомлениями попадают в журнал аудита.
