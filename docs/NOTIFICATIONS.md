# Уведомления

Панель умеет сообщать о проблемах сама: Telegram-бот, произвольный webhook или
оба канала сразу. Настройка — **Настройки → Уведомления**.

## События

| Событие | Когда отправляется |
| --- | --- |
| `node_offline` | сервер не отвечает дольше `DFX_NODE_OFFLINE_AFTER` секунд (по умолчанию 180) или Xray на нём остановлен |
| `node_recovered` | сервер вернулся в строй |
| `user_limit` | клиент исчерпал лимит трафика или истёк срок подписки |
| `update_available` | вышла новая версия панели на GitHub |

Каждое событие включается отдельным тумблером. Проверка идёт фоновым воркером
каждые 90 секунд; состояние хранится в настройке `notify_state`, поэтому одно и то
же событие не отправляется повторно, пока состояние не изменится.

## Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен вида
   `123456789:AA...`.
2. Напишите боту любое сообщение (или добавьте его в группу).
3. Узнайте `chat_id`: `https://api.telegram.org/bot<TOKEN>/getUpdates` — поле
   `message.chat.id`. Для групп id отрицательный, например `-1001234567890`.
4. Вставьте токен и chat id в панели, включите «Отправлять уведомления»,
   нажмите «Тестовое сообщение».

Сообщение приходит в формате:

```
🔴 Сервер не в сети
DF · Frankfurt (de1.df-xray.net:443)
последняя связь: 2026-11-14T09:12:03Z
```

## Webhook

POST с JSON-телом:

```json
{
  "event": "node_offline",
  "title": "Сервер не в сети",
  "text": "DF · Frankfurt (de1.df-xray.net:443)",
  "panel": "https://panel.example.com",
  "time": "2026-11-14T09:15:00Z",
  "version": "1.3.0"
}
```

Удобно принимать в n8n, Make, Alertmanager-релей или собственный бот: панель
считает доставку успешной при ответе 2xx.

## Ручные проверки

```bash
# отправить тестовое сообщение во все настроенные каналы
curl -s -X POST -H "Authorization: Bearer $TOKEN" https://panel.example.com/api/notifications/test

# прогнать проверку событий немедленно (вместо ожидания воркера)
curl -s -X POST -H "Authorization: Bearer $TOKEN" https://panel.example.com/api/notifications/check

# текущие настройки и очередь
curl -s -H "Authorization: Bearer $TOKEN" https://panel.example.com/api/notifications
```

Ответ `/api/notifications/check` содержит список отправленных событий — удобно для
отладки после того, как вы погасили ноду или выставили клиенту лимит.

## Ограничения

- Панель не хранит историю уведомлений: только текущее состояние, чтобы не спамить.
  История событий — в журнале действий (`/api/audit`).
- Отправка идёт из фонового потока с таймаутом 10 секунд; недоступный webhook не
  блокирует панель, ошибка видна в логе процесса (`[dfxray] notify: …`).
- Уведомления не заменяют мониторинг: если упал сам VPS с панелью, сообщения не уйдёт.
  Для этого держите внешний аптайм-монитор на `/healthz`.
